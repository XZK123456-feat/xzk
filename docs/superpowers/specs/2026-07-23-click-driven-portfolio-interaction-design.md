# 点击式作品集交互改版设计规格

日期：2026-07-23  
状态：已确认  
基准版本：GitHub Pages 线上版本，提交 `7f3777d`

## 1. 背景

当前作品集由首页三个纵向区块和四个独立详情页组成，详情页继续通过长页面滚动浏览。虽然信息完整，但大量标题卡、边框、导航、作品网格同时出现，导致层级偏弱，页面更像多个 UI 模块的集合。

本次改版在不改变现有作品内容、品牌黄色和主要页面 URL 的前提下，将全站改造成点击式浏览体验。页面使用固定主舞台、明确任务层级和分页作品画廊，让招聘方一次只处理一个主要决策。

## 2. 目标

- 全站主体由滚动浏览改为点击切换。
- 首页直接展示任务目录和真实代表作品。
- 四个详情页使用统一、可预测的分类和分页逻辑。
- 保留现有黑、白、黄色视觉识别，同时减少边框、阴影和卡片堆叠。
- 桌面端和移动端使用同一套任务结构。
- 保留独立详情页 URL、分享能力、浏览器历史和无 JavaScript 降级路径。
- 提升加载稳定性，幕布结束后字体和当前屏关键图片必须已经就绪。

## 3. 非目标

- 不更换现有作品图片、视频、简历或文案口径。
- 不将四个详情页合并为单页应用。
- 不增加 3D 倾斜、磁性悬停、自定义光标、音效或高频视差。
- 不要求初次加载时下载全部图片和视频。
- 不删除现有 Lightbox 的缩放、翻页和触摸能力。

## 4. 已确认设计方向

| 决策 | 选择 | 说明 |
| --- | --- | --- |
| 全站结构 | B2 全屏任务展开 | 任务详情接管主舞台，任务轨道持续可用 |
| 首页入口 | 直接进入任务目录 | 不增加身份封面或二次进入按钮 |
| 目录版式 | D2 主舞台 + 编号轨道 | 一次突出一个任务，减少入口拥挤 |
| 作品浏览 | W1 分类标签 + 固定分页 | 分类、画廊、分页形成稳定层级 |
| 主换场动效 | M1 黄色机械遮罩 | 用于任务进入、返回目录和主分类换场 |
| 移动端任务导航 | N2 右侧悬浮编号轨道 | 默认收窄，展开时覆盖而非挤压作品 |

## 5. 全站信息架构

### 5.1 首页

首页打开后直接进入 D2 任务主舞台：

- 顶部只保留品牌、目录、数据和简历入口。
- 中央展示当前任务的编号、名称、简短职责和一张真实代表作品。
- 固定编号轨道提供 NO.1 至 NO.4 的点击切换。
- “进入任务”是当前舞台唯一主行动。
- 点击编号只切换主舞台，点击“进入任务”才进入独立详情页。
- 首页不再纵向排列身份区、目录区和数据区。

数据内容改为独立全屏面板，并使用固定分页；简历入口打开站内全屏预览，同时保留打开 PDF 的明确按钮。

### 5.2 详情页

四个详情页继续使用现有文件：

- `website-design.html`
- `ua-creatives.html`
- `community-creatives.html`
- `video-design.html`

每个详情页固定为一个主舞台，由以下区域组成：

1. 顶部任务栏：返回、任务编号、任务名称、当前进度。
2. 任务轨道：NO.1 至 NO.4，允许跨详情页切换。
3. 分类标签：项目概览和该任务的作品类别。
4. 固定作品画廊：只显示当前页作品。
5. 分页控制：上一页、页码或页点、下一页。

正文不依赖页面滚动。内容超过一屏时必须分页，不通过继续缩小字体或作品来硬塞。

## 6. 各详情页内容映射

### NO.1 官网视觉设计

- 项目概览
- 移动端
- PC 端
- VibeCoding

横版官网图桌面端每屏 2 至 4 张，移动端每屏 1 张。竖版图桌面端每屏 3 张，移动端每屏 1 至 2 张。

### NO.2 买量图片设计

- 项目概览
- 横图素材
- 竖图素材
- 九图素材

桌面端横图每屏 4 至 6 张，竖图每屏 3 至 4 张。具体数量通过容器尺寸和图片比例决定，但同一分类内保持稳定。

### NO.3 运营图片设计

- 项目概览
- 小恐龙派对
- 不休的乌拉拉
- 狸狸汤泉

每个项目独立记录当前页码。离开分类再返回时恢复此前位置。

### NO.4 AI 视频设计

- 项目概览
- 运营社群视频
- 买量视频混剪

运营社群视频桌面端每屏 3 条，共两页；移动端每屏 1 条。买量视频混剪使用单独的大型播放器。播放新视频、切换分类、切页或离开页面时暂停其他视频。

## 7. 响应式结构

### 7.1 桌面端

- 主舞台使用 `100dvh`，页面背景不滚动。
- 任务轨道使用窄版纵向编号。
- 分类和分页始终位于固定区域，作品加载和标签长度不得改变整体布局。
- 作品舞台优先使用实际宽高比，避免横图四周出现大面积黑色空白。

### 7.2 移动端

- 使用 N2 右侧悬浮编号轨道。
- 收起状态宽度约 34px，仅显示编号和当前黄色状态。
- 点击后覆盖式展开任务名称，不永久压缩作品宽度。
- 点击轨道外区域、选择任务或按返回键后收起。
- 轨道和分页适配 `safe-area-inset-*`。
- 对高度不足的设备减少每页作品数量，禁止通过压缩文字和按钮造成重叠。

## 8. 交互与状态

### 8.1 URL 与历史

当前分类和页码写入 URL Hash，例如：

```text
ua-creatives.html#horizontal-p2
community-creatives.html#lili-tangquan-p3
```

- 首次进入根据 Hash 恢复状态。
- 分类、页码和任务切换写入浏览器历史。
- 前进、后退恢复对应页面状态。
- 刷新后不重置到概览或第一页。

### 8.2 Lightbox

- 点击画廊作品打开现有 Lightbox。
- 打开后锁定背景交互和滚动。
- 关闭后恢复到触发按钮及原分类、原页码。
- 支持左右箭头、键盘方向键、缩略图和触摸操作。
- 预取相邻两张大图，减少翻页卡顿。
- 只有明确的外层安全背景区域可以点击关闭；控件、图片及安全边距不会触发关闭。

### 8.3 键盘与焦点

- 分类使用 `tablist`、`tab` 和 `tabpanel` 语义。
- 左右方向键支持分页，`Esc` 关闭 Lightbox、轨道或全屏面板。
- 所有交互控件提供统一 `:focus-visible`。
- Modal、Lightbox 和展开轨道具备焦点管理及关闭后焦点恢复。

## 9. 视觉层级

- 保留黑、白、黄色，建议比例为 65% 白灰背景、25% 黑色结构、10% 黄色强调。
- 删除装饰性虚线。
- 边框只用于导航、选中项、必要控件和作品交互边界。
- 阴影只用于当前激活层，不让所有容器同时浮起。
- 页面由固定导航、任务标题、作品主舞台和分页控制四层组成。
- 任务编号可以使用大号字体；标签、说明和按钮整体缩小。
- 首页主舞台必须使用四个任务的真实代表作品。
- 不使用卡片嵌套或四周漂浮的独立页面卡片。

## 10. 动效系统

### 10.1 黄色机械遮罩

用于：

- 首页进入任务。
- 详情页返回目录。
- 主分类换场。
- 跨任务切换。

时长约 550ms。黄色面板覆盖舞台后替换内容，再退出屏幕。遮罩期间不得露出未加载字体或空白图片。

### 10.2 次级反馈

- 普通分页使用 180 至 240ms 的轻微位移和淡入。
- 按钮使用短促黄色填充反馈。
- 不在高频翻页中重复整屏机械遮罩。
- `prefers-reduced-motion` 下关闭扫屏和大幅位移，只保留瞬时淡入。

## 11. 加载与性能

- 每次进入首页或任意详情页显示简约加载幕布。
- 进度由样式、脚本、主字体和当前首屏可见图片的真实加载状态计算。
- 幕布结束前使用 `document.fonts.load()` 验证主字体。
- 字体失败时显示稳定的备用字体，不在进入页面后继续替换。
- 首屏完成后立即进入；下一页图片在后台有限预取。
- 视频只在用户点击播放时设置源并加载。
- 页面换场保留上一帧，黄色遮罩覆盖关键资源切换。
- 加载控制器保留超时放行和重试入口。
- Service Worker 更新缓存版本，旧缓存不得继续覆盖新结构。

## 12. 渐进增强与失败状态

- 只有 JavaScript 初始化成功后才启用固定舞台和 `overflow: hidden`。
- 脚本失败时退回当前可滚动文档，全部作品仍可访问。
- 图片失败显示统一占位和重试按钮。
- 视频失败保留封面和重试，不显示无解释的黑框。
- 媒体错误不得改变固定画廊尺寸。

## 13. 验收标准

### 功能

- 首页和四个详情页均不依赖正文长滚动。
- 所有任务、分类和页码均可点击访问。
- URL Hash、刷新、前进和后退正确恢复状态。
- Lightbox 不允许背景交互，关闭后位置和焦点正确。
- 同时最多播放一个视频，切页和切分类会暂停视频。

### 响应式

验证视口：

- 1920×1080
- 1440×900
- 1280×720
- 390×844
- 360×800
- 320×568

所有视口均不得出现横向溢出、控件遮挡、文字截断、意外背景滚动或横版作品被轨道长期压缩。

### 性能与稳定性

- 加载进度反映真实关键资源状态，不固定停在某个百分比后跳满。
- 幕布结束后主字体和当前屏关键图片已稳定。
- 初次加载不请求全部视频。
- 图片分页预取有边界，不一次下载整个图库。
- 无 JavaScript 时仍能访问完整内容。

### 无障碍

- Tab 可访问所有控件。
- `focus-visible` 清晰可见。
- Modal 和 Lightbox 焦点不会逃逸。
- 动态状态通过适当 ARIA 属性和 live region 更新。
- 减少动态效果设置得到尊重。

## 14. 实施原则

- 在当前线上基准版本上修改，不使用此前放弃的视觉实验版本。
- 优先复用现有 HTML、图库数据和 Lightbox 逻辑。
- 将共享点击舞台、分页、历史和加载逻辑集中到公共模块，页面脚本只提供各自数据。
- 每个阶段完成后进行桌面和移动端截图检查，再进入下一阶段。
- 完整验证通过后再同步 GitHub Pages。
